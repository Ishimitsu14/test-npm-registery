# berish-context

Служит для передачи контекста внутрь по дереву вызовов. Полезно, когда у нас есть параллельные потоки, и мы хотим передать внутрь каждого потока данные. Каждый поток видит только свои данные.

# Использование

Для начала нам необходимо создать контекст. Это объект, с помощью которого мы может задать данные, которые внутрь потока надо передать, а так же вытащить данные внутри самого потока.

## Создание контекста

```typescript
export const IP_CONTEXT = new Context<string>(null); // Здесь можно прокинуть значение по-умолчанию. Если контекст ни разу не задавал значение в потоке, потребитель получит default значение (не обязательный параметр, по-умолчанию undefined)
```

## Передача значений

```typescript
export async function middleware(request: RequestPayload, next: NextFunction) {
    const ip: string = ...; // Например получили ip из запроса

    const result = await IP_CONTEXT.run(ip, () => next()); // Теперь нам не надо прокидывать запрос, или загрязнять общий объект. Кому надо, внутри потока сможет получить значение

    return result;
}

```

## Получение значения

Допустим, из примера выше, что метод `testMethod` вызывается внутри `next` метода (который был в middleware)

```typescript

export function testMethod() {
    const ip = IP_CONTEXT.getValue(); // в этот момент мы получим значение, которое нас интересует

    // ИЛИ

    const ip = useContext(IP_CONTEXT);
    ...
}

```

## Что есть еще?

Есть `ContextData`. Он позволяет создать объект, в котором сразу есть значение. Когда это полезно? Например, мы хотим за 1 раз указать несколько разных контекстов с разными данными. Чтобы избежать callback hell, мы можем сделать это одним методом

```typescript
const IP_CONTEXT = new Context<string>();
const TOKEN_CONTEXT = new Context<string>();

const result = await runAll(
  () => {
    // Здесь внутренний поток
  },
  IP_CONTEXT.createContextData('127.0.0.1'),
  TOKEN_CONTEXT.createContextData('token'),
);

// Такой подход намного удобнее, нежели

const result = await IP_CONTEXT.run('127.0.0.1', () => {
  return TOKEN_CONTEXT.run('token', () => {
    // Внутренний поток
  });
});
```

---

- `useContext` - позволяет просто использовать данные в потоке из контекста
- `distinct` - Если у нас один и тот же контекст переписывает данные, мы можем спокойно сделать уникальное дерево контекстов
- `runAll` - Прокидывает сразу несколько контекстов в один поток
- `bindAll` - То же самое что `runAll`, только не вызывает сразу `callback`, а возвращает функцию, которую можно вызввать позже

# Для чего это все?

- Мы можем прокидывать значения внутрь, и не загрязнять метод лишними параметрами.
- Может показаться, что мы могли бы использовать Singleton подход. Но это не так. Если бы мы в Singleton задали бы значение, оно было бы равным для всех потоков. Это не позволяет для каждого контекста задавать свои, индивидуальные данные.
- Контексты прекрасно поддерживают Promise, Callback. Мы можем передавать данные и не переживать, что какой-то поток может получить данные из чужого потока.
